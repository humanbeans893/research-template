# experiments/ — 実験ディレクトリ

試行錯誤の実験を、番号付きディレクトリとして蓄積する場所です。**1 実験 = 1 ディレクトリ**で自己完結させます。規約の正は `AGENTS.md` の Experiments で、この文書はその日本語版です(変えるときは両方を同じ編集で直す)。

## 3つの文書

| ファイル | 役割 | 書くとき |
|---|---|---|
| `EXP_SUMMARY.md` | 全実験の索引(1実験1行)。撤回・訂正を一目で分かるようにする。毎セッション読む | 実験を作ったとき、状態や結論が変わったとき |
| `NNN_<slug>/summary.md` | その実験の今の結論(状態・問いと判定の規則・答えと言えないこと・主な数値と出所・本実行)。短く保つ(上限はテストが検査する) | 作成時に問いと判定の規則、本実行の後に答えと数値。結論が変わったら書き直す |
| `NNN_<slug>/README.md` | 経緯の記録(目的・方法・結果・考察・訂正) | 意味のある実行のたびに日付をつけて追記する。古い記述は消さない |

読む順は 索引の行 → `summary.md` → `README.md`。ほかの実験を前提にしたり引用したりする前に、その `summary.md` を読む。`README.md` は方法を再現・拡張・点検するときに開く。

## 命名と構成

- `NNN_<slug>/`(ゼロ埋め3桁の連番 + 小文字・数字・`_` の短い英語)。例: `001_baseline_fit/`
- 番号は使われている最大値 + 1。実験ディレクトリと索引の行は消さない(やめた実験は「中止」にする)ので、番号が使い回されることはない。

| ファイル | 役割 | Git |
|---|---|---|
| `summary.md` | 今の結論 | コミットする |
| `README.md` | 経緯の記録 | コミットする |
| `run.py` | 実行エントリポイント(`src/` の再利用コードを呼ぶ) | コミットする |
| `params.py` | 実験を決める値のすべて(シードを含む。`config.py` から読まずにここで固定する) | コミットする |
| `out/` | 図・ログ・中間出力と `params_used.json` | **コミットしない**(`.gitignore` 済み) |

## 新しい実験の始め方

```bash
make experiment SLUG=<slug>
```

番号を決め、`_template/` を複製し、`NNN_<slug>` と日付を埋め、索引に「進行中」の行を足します(手でやるなら `cp -r experiments/_template experiments/NNN_<slug>` の後に同じことをする)。

1. `summary.md` の問いと判定の規則を書き、`params.py` を決めて、本実行の前に一緒にコミットする。
2. `run.py` を実装する(ロジックは `src/` を呼ぶ。冒頭の sys.path ブートストラップは消さない)。
3. smoke で通し、各段の所要時間を見てから本実行する:

   ```bash
   docker compose exec research-template uv run python experiments/NNN_<slug>/run.py --smoke
   docker compose exec research-template uv run python experiments/NNN_<slug>/run.py
   ```

   `--smoke` は `params.SMOKE` の小さな値で `out/smoke/` に書き、`result/` へは昇格しません。完了した本実行は `--overwrite` なしでは上書きされません。`out/params_used.json` に状態・シード・パラメータ・コミットと未コミットのコード・各段の所要時間が残ります。
4. `README.md` に結果と考察を日付をつけて追記し、`summary.md` の答え・主な数値・本実行と索引の行を同じコミットで直す。

## 状態の語

索引の状態欄と `summary.md` の「状態」は次のどれかで始め、同じ語にする。後ろに `(YYYY-MM-DD、→ NNN_<slug>)` のように日付と根拠の実験を足してよい。

- 進行中: まだ結論がない
- 完了: 本実行が終わり、答えが立っている
- 中止: 結論を出さずにやめた
- 訂正: 一部の数値や記述を直した。主な結論は保たれる
- 撤回: 主な結論を取り下げた
- 置き換え: 後の実験が同じ問いに答え直した

## 撤回・訂正・置き換え

同じコミットで次を直す。「あとで書く」と、実際には書かれない。

1. `summary.md`: 状態と答えを書き直し、「訂正・撤回・置き換え」の行に日付と根拠を書く。取り下げた記述は消さずに取り消し線で残す(例: `~~効果は閾値によらない~~(2026-10-02 撤回 → 025_threshold_check)`)。
2. `EXP_SUMMARY.md`: 状態欄を同じ語で始める。
3. 撤回なら `docs/guardrails.md` の「撤回した主張」に1行足す。

本文で撤回した結論が、見出しや一行の要約だけを読むと生きて見える事故は、実際に起きます。`--overwrite` で本実行をやり直したときも、`summary.md` の本実行と主な数値を同じコミットで直します。

## ルール

- **過去の実験は書き換えない** — 完了した実験の `run.py`・`params.py` を変えて結果を差し替えない。条件を変えるなら新しい番号の実験を作る。`README.md` は追記と誤字の修正だけ。書き直すのは `summary.md` だけ。
- **出力はすべて自分の `out/` へ** — `out/` は Git に入らない。
- **他の実験の `out/` を読まない** — `out/` は新しく複製したリポジトリには無く、やり直しで置き換わる。後の実験・原稿が使うものは、作った実験がコード(`run.promote()` か `scripts/` のスクリプト)で `result/tables/`(小さな CSV。コミットする)か `data/processed/`(大きなもの)へ、図は `result/figures/` へ昇格させる。手でコピーしない。
- **数値には出所を添える** — `summary.md`・`README.md` に書く数値には出所の CSV(行・列)を添える。食い違えば CSV が正。
- **再利用ロジックは `src/` へ** — 2つ以上の実験で使うコードは、実験間でコピーせず `src/` に移して import する。
- `tests/test_repo_structure.py` が、名前と番号、索引との対応、`summary.md` の長さと状態の語、「進行中」を過ぎた `summary.md` に雛形の `<...>` が残っていないことを検査する。
