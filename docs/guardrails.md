## Known Pitfalls(一般則)

- 本番実行を最初の動作テスト・性能テストにしない(pilot → 投影 → 本番)。
- 結果を見た後に実験定義・評価条件を変えない(変えるなら新しい実験番号を切る)。
- 未コミットの WIP を放置したまま次の作業を積まない(commit / 退避 / 破棄のいずれかに倒す)。
- 環境ドリフト(lockfile 外のインストール、コンテナ外実行)に気づかず結果を比較しない。
- seed・設定・commit を記録しない実行結果を信用しない。
- 本文で撤回した結論を、見出しや索引の一行に生きたまま残さない。撤回は `exp/EXP_SUMMARY.md` の状態欄とこのファイルに同時に書く。
- 数値を README や原稿へ手で書き写さない。CSV からコードで生成する。書き写しは桁や小数を間違え、CSV の検査が通っても手で書いた数値は古いまま残る。
- 既定値に依存したまま結論を書かない。評価する時点・閾値・期間などの既定値を変えても結論が保たれるか確かめてから書く。
- 同じ量を、別の推定量や別の分母で比べない。比べる2つは同じ定義・同じ集合で計算する。
- 本文を直したら、補足資料・図表の説明・要旨も同じ作業で直す。片方だけ直すと食い違いが残る。
- 原稿を縮めるときは、主張の限定(条件・例外・頑健でないこと)を一緒に落としやすい。縮めた後に限定が残っているか確かめる。
- 図の重なりや見え方を、文字や画像の配置の計算だけで「問題なし」と報告しない。描画した画像を実際に見て確かめる。
