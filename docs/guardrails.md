# 繰り返さないこと

このプロジェクトで繰り返してはいけない失敗と、撤回した主張を記録します。毎セッションの最初に読むので、1件1行にし、詳しい経緯は該当実験の `summary.md`・`README.md` や `docs/` の研究ログへ書いてリンクします(長さの上限は `tests/test_repo_structure.py` が検査します)。特定の実験の読み方や、その実験から言ってはいけないことは、その実験の `summary.md` の「言えないこと」に書きます。

## よくある落とし穴(一般則。このプロジェクトに合わせて削ってよい)

- 結果を見た後に実験定義・評価条件を変えない(変えるなら新しい実験番号を切るか、`summary.md` の判定の規則に「事後」と書く)。
- 未コミットの WIP を放置したまま次の作業を積まない(commit / 退避 / 破棄のいずれかに倒す)。
- 環境ドリフト(lockfile 外のインストール、コンテナ外実行)に気づかず結果を比較しない。
- seed・設定・commit を記録しない実行結果を信用しない(実験なら `out/params_used.json` を見る)。
- 数値を原稿へ手で書き写さない。CSV からコードで生成する。`summary.md`・`README.md` に書く数値には出所(CSV・行・列)を添える。書き写しは桁や小数を間違え、CSV の検査が通っても手で書いた数値は古いまま残る。
- 既定値に依存したまま結論を書かない。評価する時点・閾値・期間などの既定値を変えても結論が保たれるか確かめてから書く。
- 同じ量を、別の推定量や別の分母で比べない。比べる2つは同じ定義・同じ集合で計算する。
- 本文を直したら、補足資料・図表の説明・要旨も同じ作業で直す。片方だけ直すと食い違いが残る。
- 原稿を縮めるときは、主張の限定(条件・例外・頑健でないこと)を一緒に落としやすい。縮めた後に限定が残っているか確かめる。
- 図の重なりや見え方を、文字や画像の配置の計算だけで「問題なし」と報告しない。描画した画像を実際に見て確かめる。
