# 長時間ジョブ投入前チェックリスト

高コストな計算(HPC ジョブ、長時間の学習・解析、クラウド課金を伴う実行)の前に、
毎回このリストを上から実行します。1 項目でも落ちたら投入しません。
本番実行を最初の動作テスト・性能テストにしないことが原則です。

## 起動契約(コードが最初に踏む地雷)

- [ ] 設定ファイル・引数の読み込みを**実際に**通した(必須キー欠落・型不一致は
      起動直後に落ちる。dry-run や設定ロードだけの smoke を先に走らせる)。
- [ ] 関連するテストが pass している。
- [ ] 実行に必要な入力データ・上流成果物がすべて存在し、パスが解決できる。

## 再現性

- [ ] worktree が clean で、意図した commit を checkout している
      (`pwd && git branch && git status`)。
- [ ] 環境が固定されている(lockfile / コンテナイメージ / モジュールバージョン)。
- [ ] 乱数 seed と設定一式が出力に記録される。

## 実行設計

- [ ] 出力先は未存在の新しいパスで、既存結果を上書きしない。
- [ ] ログは成果物ディレクトリを汚さない場所に書く。
- [ ] 代表的な小規模 pilot で実測し、本番の所要時間・資源を投影した。
- [ ] 長時間ジョブは checkpoint / 再開を実証済み。
- [ ] 資源要求(ノード・GPU・上限時間・ディスク)が投影と整合している。

## 投入直後・完了後

- [ ] 投入直後: `exp/JOBS.md` へ行を追加し、`STATE.md` を更新した(`write-handoff` スキル。確認方法と結果の記録先まで書く)。
- [ ] 完了後: 結果を `exp/JOBS.md` に追記し、考察を `exp/NNN_<slug>/README.md` へ、
      経緯を `docs/` の研究ログへ記録した。
- [ ] 失敗した場合: 失敗も記録として残し、原因を `docs/guardrails.md` に追記した。
